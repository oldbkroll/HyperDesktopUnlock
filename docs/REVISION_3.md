# 第三版兼容候选：手势区域刷新与显式镜像选择

本版不是已验证修复。来自用户协作实机测试的边界：

- Unlock 开启，连接独立外屏，未改显示参数时：内屏手势正常（Extend 未运行及运行/无障碍开启两组）。
- 独立模式下，用户单独修改外屏 DPI（150→200）或缩放，均报告内屏上滑回桌面/最近任务失效；返回和通知栏仍可用。
- Unlock 关闭，重连外屏恢复手势；随后修改 Extend 显示设置正常。
- Unlock 开启，从系统连接弹窗选镜像，实际 mirror_built_in_display 仍0，外屏为未启动应用的独立桌面；不能作为镜像对照。
- Unlock 开启，从应用内按钮切镜像，实际 mirror=1；用户按测试步骤改显示设置后反馈镜像、手势正常。

原始日志/截图不入仓库。固件桌面日志在异常时把手势区域由1200×2608变为1152×2048或1440×2560；重连后恢复。手机实际显示和触控viewport始终1200×2608。这支持外屏配置污染桌面内屏手势区域的假设，但没有证明底层缺陷的唯一来源。

## 候选改动

1. 新增 system_server 的 GestureConfigHooks，仅在 popsicle / OS4.0.5.0.XPBCNXM 上安装。依据本机 services.jar 的实际方法签名，保留所有原始外屏配置通知；通知完成后，仅向登记UID属于 com.miui.home 的 IDisplayWindowListener 发送 display0 实际 Configuration 的副本。其他进程不接收额外通知，不阻断外屏通知、不改内屏显示参数、不重启桌面，不增LSPosed作用域。
2. 仅总开关开启、mirror=0、变化显示器匹配当前物理外屏时补发；镜像、关闭、内屏/背屏事件、其他外屏、未知镜像状态均不补发。失效监听器可清理，异常隔离，不替换原始方法结果。登记监测在关闭时仍保留，以便后续启用无需重启；仅功能回调受总开关控制。
3. 系统连接弹窗的显式Mirroring选择后补写mirror=1，与现有Computer补写mirror=0对称，避免核心MirrorPolicy no-op吞掉显式镜像请求。此分支仍需实机确认，不能仅凭构建认定生效。
